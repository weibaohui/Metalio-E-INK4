# 天气 动态应用

墨水屏当「第二屏」的经典形态：**一天刷几次，静默待着**。

![图标](icon.png)

## 界面

| 区域 | 内容 |
|---|---|
| 顶部 | 城市名 + 城市本地钟点（观测时刻） |
| 中间 | 七段数码管大温度（带 ℃）+ 纯几何天气图标 |
| 指标 | 天气描述 / 体感温度 / 湿度 / 风速 / 降水概率 |
| 下半 | 今天·明天·后天 三天预报（天气、最高/最低、降水概率） |
| 底部 | 更新时间、数据源、三个按钮：**城市 / 刷新 / 朗读** |

七段数码管**只画点亮的段**，灭掉的段完全不画——1bpp 上留一圈空心框或细鬼影只会把字形搞脏。

## 为什么这么设计（都是墨水屏逼出来的）

- **不跳秒**：只在数据真的变了的时候重画。自动刷新 30 分钟一次，值没变就不刷屏——墨水屏每刷一次都在老化。
- **断网不白屏**：读数缓存在 app 自己的 `data/weather.txt`，下次打开先显示上次读数，联网成功后自动覆盖。墨水屏常待机常断电，缓存是刚需。
- **纯几何**：温度用七段数码管，天气图标（太阳/云/雨/雪/雷/雾）全是几何拼的，不用位图——1bpp 下线条比灰度清晰得多。
- **能熄屏只出声**：点「朗读」用固件的 TTS 播报天气。电子墨水相对手机/平板的独占能力：不烧屏、不耗刷新电。
- **不滚动，只分页**：墨水屏拖动会留满残影，翻页一次只刷一屏反而干净。配合字母过滤，每个字母组通常只有 1~2 页。

## 城市选择面板

353 个城市（全国地级市 + 港澳台），**按拼音首字母过滤 + 分页**：

- 底部两行 A-Z 字母条，点一下只看该首字母的城市；再点一下取消过滤
- 当前过滤的字母用黑条高亮，状态行显示「X 组 · N 个城市 · 第 P/M 页」
- 每组前有首字母标题行
- 右上角「全部」回到完整列表
- 底部「上页 / 下页 / 重载 / 取消」

## 数据源

[Open-Meteo](https://open-meteo.com/)（免注册、免 key、JSON 体积小）。固件侧用 `api::HttpFetch` 走证书包，HTTPS 握手需要 14KB 连续内部 RAM。

## 配置

两个可选文件放在 app 自己的 `data/` 目录（注意是 `.app`，点号，不是 `_app`）：

### `cities.txt` —— 自定义城市

每行一个城市，`名称,纬度,经度`：

```ini
呼和浩特,40.8414,111.7519
大理,25.6065,100.2676
```

内置 353 个城市（全国地级市 + 港澳台），自定义城市追加在后面。改完点城市面板里的**重载**生效。

### `api.txt` —— 覆盖 API 基址

一行完整基址，默认 `https://api.open-meteo.com/v1/forecast`：

```ini
https://api.open-meteo.com/v1/forecast
```

open-meteo 在某些网络下不通时，可以指向自建代理（参数名与返回结构保持一致即可）。
每次刷新都会重新读这个文件，改完点「刷新」就生效，不用重启。

## 怎么传上去

```bash
curl -X POST \
  -H "Authorization: Bearer <PIN>" \
  -H "X-Filename: cities.txt" \
  --data-binary @cities.txt \
  "http://<设备IP>:8080/fs/upload?path=apps/weather.app/data"
```

## 按键

| 键 | 动作 |
|---|---|
| 触摸「城市」 | 打开城市选择面板 |
| 触摸「刷新」 | 立即联网取一次 |
| 触摸「朗读」 | TTS 播报当前天气 |

## 城市库怎么来的

`main/city_db.h` 是 `gen_cities.py` 自动生成的（别手改）：

```bash
cd tools/weather_app
python3 -m venv /tmp/pinyinenv && /tmp/pinyinenv/bin/pip install pypinyin
/tmp/pinyinenv/bin/python gen_cities.py
```

- 城市清单：内置（带省份，用于校验）
- 经纬度：open-meteo geocoding API。**中文字段查询覆盖不全**（常州/温州/厦门/朔州全查不到），
  所以用拼音查，再用返回结果的中文 `admin2` 字段校验是不是同一个市；查错的走脚本里的 `OVERRIDE` 手工指定。
- 拼音首字母：pypinyin；多音字读音和地名实际读法对不上的（长治→zhangzhi）在 `INITIAL_FIX` 里订正。

## 已知坑

- **换 .so 必须重启设备**：动态应用的界面实例被框架缓存复用（日志里是 `lifecycle: resume app xxx` 而不是 `create`），重装同 id 的 .so 后界面还是旧的。
- **固件导出表里没有 `__fixdfsi`**：double→int 的转换没导出，所以本应用全程不碰浮点——坐标按「度 ×10000」存成整数，JSON 里的数字用 cJSON 已经算好的 `valueint`，四舍五入靠 `__floatsidf`/`__subdf3`/`__gedf2` 这几个导出助手拼出来。
- **`memchr` 也没导出**：解析城市库用自己写的 `find_chr()`。
- **别在 app 里写超过 ~90 个可点对象**：设备的触觉区表只有 96 项。城市面板的字母条因此用「一块透明点击层 + 26 个文字标签」实现，而不是 26 个按钮。
- **TLS 握手会饿死网络栈**：内部内存碎片化时硬发 HTTPS 可能把 lwIP 打挂（整机软死：WiFi 掉线、HTTP 端口全无响应）。所以取数前先看最大连续块（`dynapp_sysinfo_get`），不够就等 2 分钟再试；首次取数也延后 8 秒，避开刚开机那会儿的网络碎片化。
