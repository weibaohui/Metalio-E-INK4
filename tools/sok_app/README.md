# 推箱子 动态应用（sok）

经典 Sokoban，一步一刷，适配墨水屏低刷新率特性。

![界面](../docs/mockups/sok-person-cute-device.png)

## 界面

| 元素 | 画法 | 为什么 |
| --- | --- | --- |
| 地板 | 白底 + 1px 格线 | 格子结构一眼可见；**少了格线，墙就变成一大片黑背景** |
| 墙 | 40×40 圆角黑块，四周留 2px 白缝 | 一格一格的"砖"，不是连成一片的黑（原来满格实心墙会被看成黑背景） |
| 箱子 | 32×32 实心黑方块 + **3 条白色横带** | 木板箱的条纹纹理，跟纯黑的墙砖一眼分得开（空心框、纯方块都会跟墙混） |
| 目标点 | 粗黑靶心（环 + 中心点） | 小圆点在 1bpp 上就是个脏点；靶心才像"目标" |
| 箱子归位 | **整个反色**（白底黑条 + 黑框） | 一眼看出这箱已到位；靶心被箱子盖住，由箱子自己表示状态 |
| 人 | **一个可爱小人**：大头 + 白色方眼 + 笑嘴 + 呆毛 + 圆胖身子 | 原来画"实心黑点 + 白描边"，用户反馈"哪个是用户，黑点很难理解"→ 画成小人；再按"可爱一点"加了五官和呆毛 |

> 斜纹（45°）在 1bpp 上要么糊、要么要重刷固件才能画（`lv_obj_set_style_line_width` 没导出），
> 所以横带用纯矩形子对象画，最干净。箱子用**对象池**（最多 6 个箱子 × 3 条带 = 24 个对象），
> 比"每格一个箱子"省一半 LVGL 堆。

这套画法是照成熟推箱子游戏的通用做法翻译的：**每个格子是一个独立的 tile**，
墙是深色 tile，箱子/人是画在 tile 上的物件。1bpp 没有颜色，就靠"填充 + 形状"分层，
每个元素一个唯一形状。

## 灰度模式（Bayer 网点）

墨水屏物理只有黑白两色，**没有真灰阶**。"灰"只能靠**有序抖动（网点）**模拟。
左下角有个「灰度」开关，一键在黑白 / 网点灰之间切换（状态存在存档里）。

![黑白 vs 网点灰](../docs/mockups/sok-gray-compare.png)

灰度模式的层次：**白地板 < 浅灰墙 < 中灰目标 < 黑箱/人**

| 元素 | 黑白模式 | 灰度模式 |
| --- | --- | --- |
| 墙 | 实心黑砖 | **25% 网点浅灰砖**（不再是死黑一片，箱子立刻跳出来） |
| 目标格 | 白底 + 黑靶心 | **50% 网点中灰地砖** + 白环黑心靶心 |
| 箱子 / 人 | 黑底白带 / 实心圆 | 不变（保持最深的黑） |

实现见 `main/sok_gray.h`，跟固件首页的卡片灰底（`main/display/screen/home_screen/home_screen.cc`
的 `GrayDitherImg()`）是同一套做法：

- 生成 8×8 的 `LV_COLOR_FORMAT_L8` 小图（0x00 = 黑点，0xFF = 白点），4×4 Bayer 每个格放大成 2×2 像素块；
  阈值 t → 黑点占比 t/16（墙 t=4 → 25%，目标 t=8 → 50%）。
- LVGL 用 `bg_image_src` + `bg_image_tiled` 平铺；`bg_opa` 必须设成 `LV_OPA_TRANSP`，
  否则实色底会把网点盖掉（`bg_image_opa` 默认就是 `LV_OPA_COVER`，不用另外设）。
- LVGL 把 L8 混到 I1（1bpp）上是**硬阈值**（`src > 127` → 白，否则黑，见
  `lv_draw_sw_blend_to_i1.c` 的 `l8_image_blend`），所以网点是精确的黑白点阵。
- ⚠ **网点相位以对象自己的左上角为原点**（`lv_draw_image_tiled_helper` 从对象原点开始铺），
  每块砖/每格的相位都不同。另外 LVGL 子对象定位在父对象的**内容区**内（父有边框就再往里缩），
  所以墙砖实际画在 `cell + 1(边框) + 2(局部坐标) = cell + 3`。写效果图脚本时按这个算才对得上真机。

**网点底上不要画黑色细线**——会被网点吃掉。所以灰度模式下靶心改成**白环 + 黑心**：
白是网点里最"亮"的，白环立得住，黑心再压住中心。

真机像素校验（`docs/mockups/verify_sok_render.py`）：墙 24.5% 黑、目标底 50.0% 黑、箱子 67.2% 黑。

## 画小人（1bpp 下怎么画人）

1bpp 没有斜线、没有灰度，画人只能靠**圆 + 矩形**拼。但"可爱"只能靠**形状**：
大头比例 + 五官 + 呆毛。`main/sok_main.c` 的 `mk_person_part()`（黑块）和
`mk_person_white()`（白块）负责拼，当前是「可爱版」：

| 零件 | 尺寸 | 位置（相对 32×32 的人框） |
| --- | --- | --- |
| 头（圆） | 13×13 | (10, 2) |
| 呆毛 | 2×3 | (15, 0) |
| 左眼 / 右眼（白） | 2×2 | (13, 7) / (18, 7) |
| 笑嘴（白） | 4×1 | (14, 11) |
| 身子（圆角 4px） | 10×8 | (11, 15) |
| 手臂 | 18×3 | (7, 17) |
| 左腿 / 右腿 | 4×8 | (11, 23) / (17, 23) |

![改前改后](../docs/mockups/sok-person-cute-compare.png)

⚠ **五官必须创建在头之后**：LVGL 后建的画在上层，眼睛/嘴是"黑头上的白"，
顺序反了会被黑头盖住、脸就没了。
⚠ 腿要**接在身子下沿**（y=23 = 身子末行+1），中间留 2px 缝；算错就会变成"断腿"。
⚠ 手臂别太长：22px 会让小人看着像"十字"，18px 才像胳膊。
⚠ 圆角半径会被 LVGL 夹到 min(w,h)/2，所以 10×8 的身子写 5 也等于 4。
⚠ 不用再画白描边：现在是 tile 式布局，墙砖四周留了 3~4px 白缝，小人和墙/箱子之间
天然隔着白，不会粘连。

多版造型对比（含"招手"等被否掉的方案）：`docs/mockups/make_person_variants.py`
→ `docs/mockups/person-variants.png`。

![小人](../docs/mockups/sok-person-cute-zoom.png)

## 操作

- 滑动屏幕 / 屏幕下方方向键 / 盖板上下键 → 移动与推箱子
- 悔棋 / 重开 / 下一关 → 底部按钮
- 灰度 → 左下角按钮，切黑白 / 网点灰

## 关卡生成（重要，别乱改）

关卡是**逆向生成**的：从"箱子都在目标点"的终局出发，反向**拉**箱子若干步，
得到的局面保证有解（构造出来的），不用手写关卡表。

- 生成逻辑在 `main/sok_gen.h`（纯逻辑、无 LVGL 依赖），`main/sok_main.c` 只负责把结果搬进棋盘。
- ⚠ **逆向是"拉"不是"推"**：玩家退一步、箱子跟进。正向把这串拉倒过来放才是解。
  写成"推"（玩家站在箱子反方向把箱子推离目标点）的话，正向就再也推不回来——
  箱子被顶到墙边、人要站到墙外去推，**89%~98% 的关卡直接死**（实测 400 种子/关）。
- 另有"死箱体检"兜底：只看墙都推不到目标点的箱子 → 直接换关。
- 存档格式 `SOK3`：比 `SOK2` 多了灰度开关位；`SOK2` 的老存档也照读（灰度默认关）。

## 悔棋栈要记"这一步是否推了箱子"

`s_undo[]` 里存的是 `方向 | (推了箱子 ? 4 : 0)`，存档里写成 `'0'..'7'`。

⚠ 只记方向是不够的：光看方向没法区分"走过去"和"推着箱子走"，悔棋时会把没被推的箱子也拖回来。
老代码查的是"人上一格有没有箱子"，而箱子推走后根本不在那儿 → **推箱子的那一步永远退不回来**。

## 同 app 重开时，别在 LV_EVENT_DELETE 里清全局指针

固件对"同 app 重开"的处理是：**新屏先加载、旧屏随后卸载**（见 `main/core/app_manager.cc`
的 `DispatchScreenLifecycle`）。所以 `on_screen_deleted` 里必须判断一下是不是当前屏：

```c
if(lv_event_get_target(e) != s_scr) return;   // 旧屏卸载别动新屏的状态
```

否则旧屏卸载会把**新屏**的对象指针一起清空 → App 变僵尸：画面停在旧状态、点击无反应、标签不再更新。
（`backup_app` / `badge_app` 也有同样的坑，已一并修；`parking_app` 也有，用户自己的代码没动。）

## 主机端自检（改生成器后必须跑）

```bash
cc -O2 -o /tmp/sok_gen_test tools/sok_app/test/sok_gen_test.c && /tmp/sok_gen_test 400
```

用 App 上机的**同一份** `sok_gen.h` 批量生成关卡，并用"把拉箱序列倒过来放"做构造式验解：
每一关都必须能推完通关。改生成器后没跑这个测试，等于没测。

## 校验渲染与状态是否一致

墨水屏截图可能是旧帧，肉眼也容易看错（黑箱/白箱、灰底/白底）。以**设备存档**为准做逐像素比对：

```bash
curl -s -H "Authorization: Bearer <PIN>" \
  "http://<设备IP>:8080/fs/download?path=apps/sok.app/data/sok.txt" -o /tmp/sok.txt
python3 docs/mockups/verify_sok_render.py <截图.png> /tmp/sok.txt
```

`docs/mockups/make_sok_gray.py` 生成 1:1 参照图（与 App 同几何规则），两者逐格 diff。
校准后平均每格差 0.19%（最大 1.45%，是玩家圆边缘）。

## 墨水屏注意

- 一步一刷：只脏"人 + 箱子 + 目标点"几个对象，脏区很小。
- 每 8 步全刷一次清残影（大块黑色被抹掉后会留灰影）。
  `dynapp_epd_full_refresh()` 只是置标志位（`RequestNextFullRefresh`），不会阻塞，可以放心调。
- 禁动画。

## 构建 / 部署

```bash
./tools/package_app.sh tools/sok_app                        # 本地打包
./tools/package_app.sh tools/sok_app --upload <IP> --pin <PIN>   # 热装到真机
```

> ⚠ 热装会替换磁盘上的 `.so`。**别在 App 正在运行时热装完立刻重开它**——出过整机 UI 卡死
> （LVGL 任务不响应，HTTP 还能通）。稳妥做法：先退到桌面 / 重启设备，再启动新版本。
