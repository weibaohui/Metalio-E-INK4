# 收款码 动态应用

把微信 / 支付宝收款码摆在墨水屏上，客人扫码付款。

![界面](icon.png)

## 为什么单独做一个

名片是「我是谁」，收款码是「收钱」——场景完全不同。摊主把设备立在台面上，
客人扫一下就付了，屏幕要**大、清楚、只有一个码**。塞进名片里跟一堆身份信息
挤在一起，两边都看不清。

## 界面

```
┌──────────────────────────────┐
│ 收款码                        │
│  微信收款   支付宝   备用微信    │  ← 点标签换码
│  ┌───────────────────────┐   │
│  │                       │   │
│  │     大收款码图片        │   │
│  │                       │   │
│  └───────────────────────┘   │
│         微信收款               │
│       13800000000              │
│  [重载] [怎么改]        点码全屏  │
└──────────────────────────────┘
```

- **点一下码 → 全屏展示**：整屏只剩一个 440px 的大码，递给客人看最清楚（再点一下退回）
- 彩色收款码会被自动灰度 + Bayer 抖动适配 1bpp，微信/支付宝的码本来就黑白高对比，扫得动
- 整屏展示时码铺到 440px，是全屏最大的一只，递给客人最稳

## 设计参考

- **「双码并存」是痛点** → 市面上的聚合码（微信+支付宝二合一）。聚合码的原理是
  **一个 URL 码，扫码后按 User-Agent 判断是微信还是支付宝，再跳对应收款码**。
  但那需要一台公网服务器做跳转——墨水屏设备是纯离线的，做不了。
  所以这里用最诚实的形式：**多张收款码摆出来，点标签切换**。
- **「支付活码」**：多张码轮换（商家换号也不影响收款）→ 支持配多张备用码。
- **收款码被偷换的防盗思路**（码中间加 logo、品牌色、边框）→ 整块界面做成规整的「码卡」，
  一眼就知道是自己的。

## 配置

`pay.txt` 放 app 自己的 `data/` 目录，收款码图片也放同一个目录：

```ini
[code]
微信收款|wechat_pay.png|13800000000
支付宝|alipay_pay.png|商户名
备用微信|wechat_pay2.png|备用账户
```

每行：**标签|图片文件名|备注（可省）**。图片支持 PNG/JPG（自动灰度 + 抖动）。

微信收款码获取：微信 →「我」→ 服务 → 收付款 → 二维码收款 → 保存图片到相册，
再传到设备的 `data/` 目录。支付宝同理（首页 → 收付款 → 收钱）。

## 怎么传上去

```bash
curl -X POST \
  -H "Authorization: Bearer <PIN>" \
  -H "X-Filename: wechat_pay.png" \
  --data-binary @wechat_pay.png \
  "http://<设备IP>:8080/fs/upload?path=apps/paycode.app/data"

curl -X POST \
  -H "Authorization: Bearer <PIN>" \
  -H "X-Filename: pay.txt" \
  --data-binary @pay.txt \
  "http://<设备IP>:8080/fs/upload?path=apps/paycode.app/data"
```

改完点「重载」生效。

## 按键

| 键 | 动作 |
|---|---|
| 触摸标签 | 切换收款码 |
| 触摸码 | 全屏展示 / 再点退回 |
| 硬件上/下键 | 上一张 / 下一张 |
| 硬件 Home 键 | 返回桌面（全屏时先退回） |
